Correct-answer saves follow two live rules: a SingleChoice question refuses a second correct option
("قم بإلغاء الإجابة الصحيحة القديمة أولاً"), so the old answer is cleared first; and `Order` is
required and must be unique in the question, but the backend never stores it (options read back
with `order: 0`) — so the dialog sends each option's display position (1…n). This is why the
client could not change the answer before: the old per-option dialog sent the stored `0`, which
collides with the other options.

**Backend blocker (item 4, Parent):** checked live 2026-10-24 — the Parent gets **403** on
`GET initial-assessment/{childId}/result` for all their children, and `Parent/GetMyChildren` /
`Parent/{childId}` carry no assessment status. The app therefore cannot know, for the Parent, whether
the assessment is completed: the gate is implemented and tested, and shows the plan as before when
the result is not readable (403). It applies automatically once the backend lets the Parent read the
result or adds a status field (`BACKEND_REQUESTS.md` #10). For the Specialist (and the Admin) the
gate works on live data today.
